# Deploying MurArt to Render

This guide explains how to deploy the MurArt Laravel wallpaper ecommerce application to Render with PostgreSQL using the included Blueprint.

## Prerequisites

- A [Render](https://render.com) account (free tier available)
- This repository on GitHub

## Quick Deploy with Render Blueprint

### Step 1: Deploy from GitHub

1. Go to [Render Dashboard](https://dashboard.render.com)
2. Click **New** → **Blueprint**
3. Connect your GitHub account if not already connected
4. Select the **MurArt** repository
5. Render will detect `render.yaml` and show the services to be created:
   - **murart-web**: Laravel web application (Docker)
   - **murart-db**: PostgreSQL database

### Step 2: Configure Blueprint Deployment

1. Review the services in the Blueprint preview
2. The following will be automatically configured:
   - PostgreSQL database with connection details
   - Environment variables (DB_*, APP_ENV, etc.)
   - Health check at `/health`
   - Pre-deploy migrations and caching

3. **Set APP_KEY** (if not auto-generated):
   - Render should auto-generate this via the Blueprint
   - If needed, generate manually: `php -r "echo 'base64:' . base64_encode(random_bytes(32)) . PHP_EOL;"`
   - Add it in the web service environment variables

4. Click **Apply** to create and deploy the services

### Step 3: Update APP_URL

After the initial deployment:

1. Go to your **murart-web** service in Render Dashboard
2. Copy the auto-generated URL (e.g., `https://murart-web.onrender.com`)
3. Go to **Environment** tab
4. Add or update `APP_URL` to your Render URL
5. Click **Save Changes** (this will trigger a redeploy)

### Step 4: Verify Deployment

1. Visit your Render URL
2. Check these endpoints:
   - `/` - Home page
   - `/papers` - Browse wallpapers/papers
   - `/shop` - Shop/catalog
   - `/health` - Health check (should return "OK")

### Step 5: Seed Sample Data (Optional)

To populate your database with sample data:

1. Go to your **murart-web** service in Render Dashboard
2. Click **Shell** tab to open a web terminal
3. Run:
   ```bash
   php artisan db:seed
   ```

## Environment Variables

The Blueprint automatically configures most variables. Here's what's included:

### Automatically Set

```bash
# Application
APP_NAME=MurArt
APP_ENV=production
APP_DEBUG=false
APP_KEY=<auto-generated>

# Database (auto-wired from murart-db)
DB_CONNECTION=pgsql
DB_HOST=<from database>
DB_PORT=<from database>
DB_DATABASE=<from database>
DB_USERNAME=<from database>
DB_PASSWORD=<from database>
DATABASE_URL=<from database>

# Cache, Session, Queue
CACHE_STORE=database
SESSION_DRIVER=database
QUEUE_CONNECTION=database
```

### Manually Add (Optional)

Add these in the Render Dashboard under Environment tab:

```bash
# Stripe (if using payment features)
STRIPE_KEY=your_stripe_publishable_key
STRIPE_SECRET=your_stripe_secret_key

# Mail (if you need email)
MAIL_MAILER=smtp
MAIL_HOST=smtp.mailtrap.io
MAIL_PORT=2525
MAIL_USERNAME=your_username
MAIL_PASSWORD=your_password
MAIL_FROM_ADDRESS=noreply@murart.com
MAIL_FROM_NAME=MurArt
```

## Architecture

### Services

- **murart-web**: Docker web service running:
  - Nginx (port 8080)
  - PHP-FPM
  - Laravel Queue Worker (background jobs)
- **murart-db**: Managed PostgreSQL database

### Build Process

1. **Frontend Build Stage**: Compiles Vite assets (CSS, JS, Tailwind)
2. **Production Stage**: Installs PHP dependencies and serves the app
3. **Pre-Deploy**: Runs migrations and caches config/routes/views

### Health Checks

The application includes a `/health` endpoint that Render uses to monitor service health.

## Manual Deploy (Without Blueprint)

If you prefer to set up services manually:

### 1. Create PostgreSQL Database

1. In Render Dashboard, click **New** → **PostgreSQL**
2. Name: `murart-db`
3. Database: `murart`
4. User: `murart`
5. Plan: **Starter** (or Free)
6. Click **Create Database**

### 2. Create Web Service

1. Click **New** → **Web Service**
2. Connect your GitHub repository
3. Configure:
   - **Name**: `murart-web`
   - **Runtime**: **Docker**
   - **Region**: Choose your preferred region
   - **Branch**: `main` (or your deployment branch)
   - **Dockerfile Path**: `./Dockerfile`
   - **Plan**: **Starter** (or Free)

4. Add environment variables (see list above)

5. Under **Advanced**:
   - **Health Check Path**: `/health`
   - **Pre-Deploy Command**:
     ```bash
     php artisan migrate --force && php artisan config:cache && php artisan route:cache && php artisan view:cache
     ```

6. Click **Create Web Service**

## Troubleshooting

### Build Fails

- **Node/npm errors**: Check that `package.json` and `vite.config.js` are valid
- **Composer errors**: Verify `composer.json` dependencies are compatible with PHP 8.2
- **Docker errors**: Check Render build logs for specific error messages

### Database Connection Issues

- Verify the `murart-db` service is running and healthy
- Check that database environment variables are correctly linked in Blueprint
- Ensure `DB_CONNECTION=pgsql` is set

### 500 Internal Server Error

- Check that `APP_KEY` is set and not empty
- Verify database migrations ran successfully (check Pre-Deploy logs)
- Review application logs in Render Dashboard

### Assets Not Loading

- Verify Vite build completed in build logs
- Check that `APP_URL` matches your Render domain exactly
- Ensure `public/build` directory was created during build

### Pre-Deploy Command Fails

- Check Pre-Deploy logs in Render Dashboard
- Ensure database is accessible before migrations run
- Verify PHP and artisan are available in the Docker container


Render will automatically rebuild and redeploy, running the pre-deploy commands (migrations, caching).

## Render Shell Access

To run commands in your production environment:

1. Go to your **murart-web** service in Render Dashboard
2. Click **Shell** tab
3. Run artisan commands:
   ```bash
   php artisan tinker
   php artisan db:seed
   php artisan queue:work
   php artisan cache:clear
   ```

## Database Management

### Running Migrations

Migrations run automatically on each deployment via the `preDeployCommand`.

To run migrations manually via Shell:
```bash
php artisan migrate --force
```

### Backup Database

1. Go to your **murart-db** service
2. Click **Backups** tab
3. Render automatically creates daily backups (retained based on your plan)
4. Click **Restore** to restore from a backup point

Or export manually via Shell:
```bash
pg_dump $DATABASE_URL > backup.sql
```

## Performance Optimization

### Caching

The pre-deploy command automatically runs:
- `php artisan config:cache` - Cache configuration
- `php artisan route:cache` - Cache routes
- `php artisan view:cache` - Cache Blade views

### Queue Workers

A Laravel queue worker runs automatically via Supervisor to process background jobs.

To monitor queue jobs via Shell:
```bash
php artisan queue:work --verbose
```

## Security Considerations

- ✅ Never commit `.env` files with secrets
- ✅ Use Render environment variables for all sensitive configuration
- ✅ Keep `APP_DEBUG=false` in production
- ✅ Regularly update dependencies: `composer update` and `npm update`
- ✅ Review Render's [security best practices](https://render.com/docs/security)

## Alternative: Railway Deployment

If you prefer Railway, the included `railway.toml` provides similar functionality:

### Quick Railway Deploy

1. Install Railway CLI: `npm i -g @railway/cli`
2. Login: `railway login`
3. Initialize: `railway init`
4. Add PostgreSQL: `railway add -d postgres`
5. Deploy: `railway up`
6. Set `APP_KEY` and `APP_URL` in Railway Dashboard

See `railway.toml` for configuration details. Railway pricing starts at $5/month with $5 credit included.
